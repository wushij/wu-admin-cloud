# 05 - 微服务测试与 CI 设计

> **基线对照**：单体 `wu-admin-copy`（Mockito 单测 + GitHub Actions）  
> **目标工程**：`wu-admin-cloud`  
> **日期**：2026-08-12

---

## 1. 目标

为微服务仓库建立与单体同风格、但贴合多模块拆分的**可回归门禁**：

| 层级 | 目标 |
|------|------|
| 单测 | 不启 Nacos/MySQL/Redis，纯 Mockito + JUnit5，秒级反馈 |
| CI | Push / PR 到 `main` 自动跑后端 `mvn test` + PC 前端 typecheck/test |
| 冒烟 | 本地/夜间可选：`scripts/smoke/smoke-test.ps1`（需已启动基础设施与服务） |

**不做（首期）**：Testcontainers 全链路集成、uni-app 自动化、真实 Feign 联调。后续可加。

---

## 2. 与单体的对齐点

| 单体做法 | 微服务做法 |
|----------|------------|
| `src/test/...` + Mockito | 各模块自有 `src/test`，同样 Mockito |
| `MybatisLambdaTestBase` 预热 TableInfo | message 等使用 LambdaWrapper 的模块自带 testsupport |
| `GlobalExceptionHandlerTest` | 落在 `wu-cloud-common`（全局异常公共实现） |
| `ChatServiceTest` | `wu-service-message` 的 `ChatServiceImplTest`（用户查询改为 mock `JdbcTemplate`） |
| `.github/workflows/ci.yml` | 根目录 CI：多模块 Maven + `wu-admin-web` |

差异说明：

- 单体同进程；云端按服务拆分 → **每个可运行/公共模块各自跑测试**，根 `mvn -B test` 聚合。
- 跨服务依赖在单测中 **Mock**（Mapper / JdbcTemplate / WebSocket / Feign），禁止在单测里连真库。

## 3. 测试分层

```text
┌─────────────────────────────────────────────┐
│ L0 冒烟（可选） smoke-test.ps1               │  端口 + 公开 API
├─────────────────────────────────────────────┤
│ L1 CI 门禁（本方案）                         │
│   · Backend: mvn -B test                     │
│   · Frontend: npm ci && typecheck && test    │
├─────────────────────────────────────────────┤
│ L2 单测（默认）                              │
│   · common: R / GlobalExceptionHandler / PermissionChecker │
│   · auth: 登录锁 / session-sign-init         │
│   · system: 用户创建 / 角色菜单绑定           │
│   · ticket: 工单流转 / 审批通过驳回          │
│   · ai: PromptAssembler                      │
│   · message: ChatServiceImpl 核心路径        │
│   · gateway: InnerApiGuard + ApiSecurity SM4 │
└─────────────────────────────────────────────┘
```

### 3.1 优先覆盖（业务价值 × 易碎性）

1. **common**：统一响应 `R`、全局异常映射、`PermissionChecker`
2. **auth**：登录失败锁定、会话签名初始化（SM3/SM4 密钥下发）
3. **system**：用户创建校验、角色菜单全量覆盖绑定
4. **ticket**：工单状态流转权限、审批通过/驳回与通知
5. **ai**：`PromptAssembler` 人设/上下文/知识块组装
6. **message**：私聊发送 / 拉黑拒绝 / 用户列表
7. **gateway**：`/inner/**` 外网 403；`X-Encrypted=1` 时 SM4 解密转发

后续按模块扩展：风格对齐单体已有用例；P2 起再上 Testcontainers。

### 3.2 命名与包约定

```text
{module}/src/test/java/com/wu/cloud/{domain}/
  ├── ...业务测试
  └── testsupport/          # 仅该模块需要时
        MybatisLambdaTestBase.java
        MybatisMockMatchers.java
```

- 类名：`XxxTest` / `XxxImplTest`
- 方法：`@DisplayName("场景：期望")` + `methodName_condition_expectation`

## 4. Maven 约定

- 父 POM 管理 `maven-surefire-plugin`（JUnit5）
- 需要单测的模块引入：

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-test</artifactId>
  <scope>test</scope>
</dependency>
```

- 本地 / CI：

```powershell
mvn -B test
# 或只跑某一服务
mvn -B -pl wu-cloud-service/wu-service-message -am test
```

---

## 5. CI 流水线

文件：`.github/workflows/ci.yml`

| Job | 内容 |
|-----|------|
| `backend` | JDK 17 + `mvn -B test`（根 POM 多模块） |
| `frontend` | Node 20 + `wu-admin-web`：`npm ci` → `typecheck` → `test` |

触发：`push` / `pull_request` → `main`，以及 `workflow_dispatch`。  
并发：同 ref 取消旧 run。

**故意不放进 CI 首期**：

- uni-app（构建重、环境差异大）
- 需本机基础设施的 smoke 脚本
- `npm run lint`（可待告警清零后纳入，对齐单体注释策略）

## 6. 本地开发检查清单

提交 / 开 PR 前：

```powershell
# 1) 改了 common/api 先装
mvn install -pl wu-cloud-common,wu-cloud-api -DskipTests

# 2) 跑相关测试（P0+P1 核心模块）
mvn -B -pl wu-cloud-common,wu-cloud-auth,wu-cloud-gateway,wu-cloud-service/wu-service-system,wu-cloud-service/wu-service-ticket,wu-cloud-service/wu-service-ai,wu-cloud-service/wu-service-message -am test

# 3) PC 前端
cd wu-admin-web && npm ci && npm run typecheck && npm run test
```

全量起服务后可选：

```powershell
.\scripts\smoke\smoke-test.ps1
```
